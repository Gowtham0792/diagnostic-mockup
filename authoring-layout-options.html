Authoring tool layout — shell options

Four different structures for the page around the steps (not the tiles themselves, which are already set). All keep the ZF blue / cyan palette and the same step content — only the navigation/chrome pattern changes.

1 · Left rail wizard

A persistent dark sidebar lists every step with a status dot (done / current / upcoming); the group picker becomes a small segmented control inside the main panel. Reads as a proper multi-step tool, not a marketing page — the step list is always visible, so users always know where they are and can jump back. Common in setup wizards (Stripe onboarding, Linear).

3 · Split summary pane

A persistent right-hand panel shows a running summary of every choice made so far (vehicle + functions), with the publish/continue action pinned to its bottom — the user always sees the whole configuration taking shape, not just the current step. Common in checkout/configurator flows (car builders, e-commerce).

4 · Minimal top progress, full-bleed step

Almost no chrome: a 4px progress line, a tiny step counter, then one large centered step filling the screen — more "consumer app" than "enterprise tool." Best if steps are simple and few; a poor fit once functions/parameters get dense, since it wastes width.
